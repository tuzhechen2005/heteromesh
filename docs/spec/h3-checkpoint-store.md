# H3 durable complete-state store

Implements H3-G03; synthetic real-scheduler evidence only. No pretrained weights or physical-device claims.

- CK01: `H3CheckpointStore(root).publish(binding, next_step, tensors, schedulers, generators)` writes a complete before-step state. `binding` contains the exact G03 identity/runtime/geometry/source fields plus current recovery epoch and evaluation count. Tensor names follow G03. Generator entries pair role with an actual torch Generator. No pickle or arbitrary executor data.
- CK02: Validate dtype, shape, finite values, layout coverage, anchors, sigma grids, both cursors, runtime and exact binding before publication. Layout digest covers geometry and position/tags/index/row-time tensor references. `layout_digest(geometry,tensors)` computes it before constructing the binding. Preserve FP32 bits; never reconstruct sigma from timestep. Official versus synthetic dimensions are bound by the caller's trusted profile digest.
- CK03: Fixed source `set_timesteps(num_inference_steps=N)` means N grid points, while the stored instance `num_inference_steps=E` means actual evaluations. Explicit stored sigmas are used verbatim, without shift/deduplication. Constructor shift is saved as FP32 and rejected if its original config cannot round-trip exactly. Source hash and installed revision are checked on both save and restore.
- CK04: Store is a private, single-job directory. A SQLite write lock serializes publishers/recovery processes. Every tensor frame and canonical manifest is content addressed, file-fsynced and directory-fsynced before atomic pointer replacement. A crash exposes either complete previous or complete new checkpoint. Windows provides process-crash atomicity only; POSIX directory fsync adds power-loss durability subject to filesystem guarantees. Failures before pointer replacement preserve old latest; unreferenced durable blobs are harmless.
- CK05: `restore(binding, new_epoch)` reads only the authenticated latest manifest, verifies every artifact and binding, reconstructs both actual schedulers and generators, then atomically publishes the same state with a strictly increased epoch. Fences old publishers. No arbitrary historical cursor selection. Next publish in one epoch advances exactly one full step; no rollback or skipping. Repeated restore requires the latest epoch. This store does not by itself replace coordinator ledger transactions; network assignment reconciliation is a separate integration gate.
- CK06: Hash mismatch, missing/truncated blob, wrong shape, NaN, changed model/profile/layout/runtime/job/epoch, partial scheduler advancement, malformed RNG state, unknown fields and unsupported generator backend all fail closed. A damaged latest checkpoint is not silently replaced by older potentially incompatible work. Existing old immutable manifests/blobs remain available for operator inspection. Private metadata is not public test output.
- CK07: Tests use real pinned MiniMaxH3Scheduler objects, FP32 synthetic latents, independent unequal sigma grids of equal length, anchors and generators. Interrupt and reconstruct at every boundary including zero and completion; compare both output trajectories and next RNG draws bitwise. Inject failures around blob/manifest/pointer publication, and between modality updates. These prove persistence behavior with actual schedulers, not pretrained H3 quality.

Memory limits are explicit per-artifact and aggregate serialized checkpoint bytes. Caller already owns live tensors; this first adapter moves each stored tensor to CPU for encoding and restores CPU tensors. CPU generator restoration is supported initially; accelerator generator relocation is refused. Future CUDA/MPS profiles require separate numerical and RNG evidence. Trusted callers supply the job binding; untrusted network clients must never receive this local filesystem API.

## Coordinator integration

[H3 ledger recovery](h3-ledger-recovery.md) supersedes CK04/CK05 publication policy **only for integrated H3 jobs**. `prepare` writes immutable state; `load(binding,digest)` is read-only. The ledger's digest is sole authority, and integrated operations never use the legacy latest pointer or legacy store restore. The original single-store public API remains compatible for standalone callers. Trusted Coordinator entry points bind full snapshots to same-job receipts and atomically recover ledger cursor/epoch.
