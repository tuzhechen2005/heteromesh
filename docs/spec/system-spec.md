# 异构分布式推理系统规格

状态：设计初稿，待研究证据核实和两轮独立评审。版本：0.1。日期：2026-10-06。

## 1. 目标与验收边界

以局域网中的 Windows 游戏本、Apple Silicon Mac 和 iPhone 共同执行同一次模型推理，增加单任务可用模型容量。首个目标工作负载为用户指定的 MiniMax H3 视频生成；具体模型身份、权重许可、模型结构、量化格式和后端支持必须经研究确认。不得沿用此前对话中的未经验证参数作为事实。

已报告设备：RTX 4060 Laptop 8GB 显存、Windows 主机 16GB 内存；M4 MacBook Air 本机确认物理统一内存 16GiB；两台 iPhone 15 目前不可供真机测试。Windows 用户确认可开机接入，尚未建立工具连接。iPhone 必须执行对最终推理结果有贡献的模型运算；仅显示进度、转发字节或重复无用计算不满足目标。可以接受慢速离线运行；初次下载完成后，运行不得依赖云推理或外部服务。

完成等级必须分别报告：协议原型、真实小模型跨设备推理、H3 组件适配、H3 真机视频端到端。通过较低等级不能声明完成较高等级。H3 无法在某后端实现时，应记录阻碍和证据，不得静默替换模型后宣布完成。

## 2. 系统分工与暂定技术选择

协调器维护设备会话、模型目录、静态执行计划、作业和检查点；计算节点执行受限的模型片段。第一版使用显式指定的静态分片，调度器依据实际可用内存与算子支持验证计划。自动重分片属于后续增量，不要求第一版在任意设备退出后无条件继续。

桌面端暂定 Python、PyTorch CUDA/MPS/CPU 适配器；iOS 暂定 Swift 原生应用，Metal/Core ML 等计算路径由算子和权重兼容性验证选择。这里是候选实现，不能推断 H3 已支持 MPS、Core ML 或手机 GPU。控制协议采用版本化 HTTPS JSON；张量走有界二进制流。语言、运行时不同不改变线上格式。

对单次去噪步骤，按有向无环计算图执行片段；步骤之间循环。第一版顺序执行单作业，避免把流水线并发误认为单任务容量扩展。初次权重分发后权重驻留或按计划从本地存储卸载，网络传递图边张量。跨层残差、条件输入、位置编码、时间步等必须显式成为片段输入，不能假定每层只有一个隐藏状态。

## 3. 规范性需求

本文中“必须”是验收要求；所有需求在测试计划中有证据路径。

| ID | 要求 |
|---|---|
| REQ-001 | Windows、macOS、iOS 节点使用同一版本化协议；未知主版本明确拒绝，未知可选字段可忽略。 |
| REQ-002 | 设备必须显式配对并鉴权；未经授权不得上传任务、读取模型、查询其他作业或接收张量。 |
| REQ-003 | 节点报告后端、受支持算子/精度/量化、实时资源预算及能力证据；不支持的图必须在执行前拒绝。 |
| REQ-004 | 张量保留命名、形状、类型、字节序、布局、长度和校验；非法/超限负载在分配前被拒绝。 |
| REQ-005 | manifest 锁定模型来源、版本、权重哈希、许可、片段、输入输出及运行时要求；禁止静默降级或替换。 |
| REQ-006 | 执行计划逐节点满足权重、激活、工作区、传输缓冲和保留余量的峰值预算；不能简单相加设备物理内存。 |
| REQ-007 | 状态转换持久化；作业提交与片段尝试有幂等键，迟到及重复结果不得被重复提交。 |
| REQ-008 | 不同平台在约定误差内实现同一片段语义；必须验证片段拼接与完整模型参考结果。 |
| REQ-009 | 有界队列和流控限制在途字节；断线、超时、节点退出必须变为可见且可恢复或可解释的状态。 |
| REQ-010 | 检查点原子保存完整恢复状态；恢复验证模型、计划、参数和状态完整性，不兼容状态拒绝恢复。 |
| REQ-011 | 同一执行 epoch 重试只补齐未提交片段；从步级检查点恢复可在新 epoch 重算已丢失的临时结果，但不能重复提交最终产物；有限次数/退避，不得在资源不足时无限重试；取消最终阻止结果提交。 |
| REQ-012 | 运行可观测：每节点真实计算、传输、资源峰值、耗时、重试及总进度；不上传提示词/张量到遥测服务。 |
| REQ-013 | iPhone 有明确前台运行、锁屏/挂起/热状态/内存压力处理；实际生命周期失败必须可检测。 |
| REQ-014 | 预装权重后，可在无互联网的局域网完整运行，并导出可播放视频及执行证据。 |
| REQ-015 | Windows+Mac+iPhone 在同一次真实模型推理中各执行有贡献的运算；最终 H3 验收不得由模拟器或小模型代替。 |
| REQ-016 | 对固定精度、分辨率、帧数及卸载策略，给出单节点容量失败与集群成功的可复现实验；不得混用不同配置夸大收益。 |
| REQ-017 | 每次实现变更走测试先行、独立智能体审查 PR、必需 CI 通过后合并；作者不得审查批准自己的 PR。 |
| REQ-018 | 模型支持受许可约束的下载恢复、本地导入、哈希校验、版本固定和安全卸载；活跃任务引用时拒绝卸载。 |
| REQ-019 | 用户可限制内存、电池参与与缓存保留，撤销节点及清理数据；操作不能越过授权根目录或删掉其他作业产物。 |
| REQ-020 | 提供干净环境安装/诊断说明和可用的提交、暂停、恢复、取消入口；暂停在完整步边界生效并持久化。 |
| REQ-021 | 后端适配器遵守统一能力、prepare、execute、cancel、telemetry 契约；新增后端无需改协议，未知能力拒绝。 |

## 4. 数据协议

协议的路由、完整线上字段、HTTP错误、二进制 framing、配对TTL、轮询/租约语义以及跨语言fixture格式以 [protocol-v1.md](protocol-v1.md) 为唯一规范。本文只定义系统级需求，不维护第二套路由或包头。两文件冲突时必须修正规格并重新评审，不能由实现自行选择更方便的一套。

控制与张量均经TLS和配对身份授权；发现服务不授予权限。客户端发送秘密前验证带外获取的协调器证书指纹。禁止pickle、任意shell/Python代码、未校验远端文件路径和静默关闭证书校验。

协议实现必须使用同一fixtures目录的精确字节进行Python/Swift双向验证；编解码支持和模型计算dtype支持分别声明。BF16编码不能被当作FP16，转换须在执行计划显式标注。受信任计划绑定张量语义与作业权限，内容哈希仅说明字节完整性，不能替代授权。

manifest/profile/plan使用protocol-v1 D-07定义的受限canonical JSON摘要；artifact摘要使用完整原始文件字节。张量尺寸、整数范围、payload预算在分配前检查；shape含零也不能跳过逐维范围检查。具体限制见protocol-v1。第一协议PR须先提交JSON schema与共享fixtures再实现；设计文件不等于schema文件已落地。

模型生命周期和本地数据清理首版通过owner CLI完成，不必暴露远程文件管理接口。模型内容按SHA256寻址，本地导入使用受控目录；下载断点同时绑定来源ETag/revision和预期完整哈希，来源变化重新下载。删除前事务检查作业引用，清理使用目录内文件句柄/路径规范检查并拒绝符号链接逃逸。

## 5. 能力、manifest 与资源预算

能力描述含稳定 node ID、平台/系统/应用版本、后端版本、设备型号、支持的 dtype/算子/量化、物理与当前可用 CPU/GPU 内存、每张量上限、存储空间、电量/供电/热状态及前台状态。未知指标为 null，不能解释成零或无限。苹果统一内存不得重复计为 CPU 和 GPU 两份。

每个 manifest 含模型规范名称、来源 URL/revision、许可、各权重分片 SHA256 与字节数、图片段输入输出规范、参数/权重映射、计算语义版本、所需算子、精度和量化配置、参考测试向量、最大配置范围。视频任务参数至少含提示词、seed、尺寸、帧数、采样器、步数、音频配置和所有改变语义的选项；模型特有字段待研究填充。任何替换编码器、量化或删减音频都作为不同 profile 明确展示。

单节点内存估计 = 驻留权重 + 最大活跃张量集合 + 运算工作区 + 传输缓冲 + 运行时开销 + 系统保留余量。共享内存平台使用一个预算；桌面独立显存与主存分别约束。准备阶段以实测样例峰值校准估计，首版默认只承诺已验证 profile 范围。发现内存不足时明确停止/降配需另建作业，不能静默降低视频质量。单算子工作区超过任何节点容量时，按层切分也不能解决，应明确报告需算子分块或其他策略。

## 6. 状态与故障语义

作业状态：`queued → preparing → running → succeeded`；`preparing/running → waiting_for_nodes`，节点重新准备通过后回到原执行阶段；`running → pausing → paused` 在完整步检查点发布后生效，resume 重新经过 preparing；可恢复错误进入 `retrying`，超过策略进入 `failed`；任意非终态可进入 `cancelling → cancelled`。取消与成功通过同一持久化提交事务竞争，先提交的终态获胜；终态不可逆。协调器重启后先恢复账本、废弃旧 session 未提交尝试，再验证 checkpoint/节点。

片段以 `(job_id, recovery_epoch, step_index, fragment_id, input_digest)` 为逻辑执行键；`attempt_id` 标识一次尝试。结果提交使用比较交换，每 epoch 内至多提交一次片段结果，不承诺物理计算恰好一次。步级 checkpoint 是持久恢复边界；重启丢失步内临时张量时递增 recovery_epoch，从最近完整步重算，旧 epoch 的未提交/冲突结果拒绝；已持久化成功的同一结果重发可以返回既有提交收据，但不重新执行或提交。最终产物以 job_id 为唯一提交键，与取消状态在同一事务中校验。重发同一提交请求返回既有作业；同键不同请求摘要返回冲突。

错误码至少包括 `UNAUTHORIZED`、`PROTOCOL_MISMATCH`、`UNSUPPORTED_OPERATOR`、`MANIFEST_MISMATCH`、`INVALID_TENSOR`、`OUT_OF_MEMORY`、`DISK_FULL`、`NODE_UNAVAILABLE`、`DEADLINE_EXCEEDED`、`CHECKPOINT_INVALID`、`CANCELLED`。只有声明 transient 的连接错误或节点暂时失联可默认重试；默认 3 次、指数退避带抖动。deadline 按实测耗时设置并允许用户调整，不能用短固定超时淘汰慢速手机。heartbeat 与长计算独立。

去噪步骤边界 checkpoint 至少包含 latent/其他循环状态、完整调度器状态、各随机数生成器状态、步索引、条件输入哈希/缓存引用、manifest/plan/profile 摘要、模型实现与运行时版本。先写临时目录并同步，再原子发布索引；空间不足保留上一完整版本。若后端只能提供数值容差恢复而非逐位恢复，必须明确声明并按容差验证。不假定仅保存 seed 即可恢复。

节点失联时冻结其依赖任务，保留已提交输出；同能力备用节点有权重且通过预算检查后才重分配，否则等待原节点恢复或明确失败。第一版不要求通过迁移正在执行的 GPU kernel 恢复；重算最近未提交片段或从最近完整检查点恢复。

## 7. 最终证据与未决项

最终交付必须附：固定 manifest/profile、设备清单及版本、计划图、每片段真实执行日志、各设备资源峰值、网络字节数、总耗时、可播放视频、离线验证及故障恢复记录。两台 iPhone 分别参与应单独记录；仅一台参与不得表述为两台均已验证。

当前开发环境证据（协调器实测）：本机有 CommandLineTools 与 Swift 6.2，无完整 Xcode/iOS SDK；Python 3.11/3.12 可用；GitHub 仓库为 `tuzhechen2005/heteromesh`。本机可以验证部分 Swift 纯逻辑，不能把这当作 iOS 应用编译或真机测试证据。

H3 模型来源与受限许可已由 [研究文档](../research/feasibility.md) 查证，实际部署须满足适用授权，不能将其称为无条件开放许可。进一步待确认：模型切分边界与实测激活规模；CUDA/MPS/iOS 各关键算子和量化可行性；设备实际可用预算；Windows 与 iPhone 执行/签名环境；GitHub 独立 review 账号约束。研究不成立时更新风险与备选实验，不改写最终目标。
