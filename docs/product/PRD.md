# HeteroMesh 产品需求文档

版本：0.1（待两轮跨代理评审）  
日期：2026-10-06  
角色：产品设计代理  
状态：产品需求草案；不代表 H3 或 iOS 推理已经验证。

## 1. 产品目的与不可替换的目标

让个人用户把现有 Windows、Mac、iPhone，以及未来增加的平台组成局域网计算集群，共同执行单次大型模型推理。第一个目标工作负载是用户指定的 MiniMax H3 视频生成。用户接受慢速、离线、长时间运行，以增加能运行的模型容量、理解异构计算和复用已有硬件为首要价值。

“组成更强的设备”在产品中的含义是统一提交作业、协调分散的内存和算力、汇总结果。它不承诺把各设备内存变成硬件一致的共享显存，也不承诺增加节点必然加速。

以下结果不能替代最终目标：只做设备发现面板；只把多个独立视频分发给不同设备；单机量化优化；仅做小模型或模拟节点演示；仅让手机充当遥控器或下载器。上述功能可用于开发验证，但必须标为中间成果。

| --- | --- | --- |

| 未来设备 | 平台未定 | 通过节点能力协议和计算后端适配接入 |

H3 的确切官方仓库、权重版本、许可、组件、参数量、所需精度、音频能力、可运行后端必须由研究文档核验。前面对话中的资源数字和社区性能记录不是产品已验证事实，不得直接作为验收证据。

## 3. 用户与使用场景

当前 Mac 仅有 Command Line Tools 与 Swift，未配置完整 Xcode/iOS SDK。可以继续开发协议、桌面执行和 Swift 纯逻辑；iOS App 编译须使用具备 SDK 的环境，签名安装和最终测试须等待真实设备。上述条件属于执行与验收缺口，不改变手机在最终产品中的范围。

1. **设备拥有者：** 启动各设备上的节点程序，配对后看到每台设备能提供的资源，选择允许的内存、电量和工作时间范围。
2. **视频创作者：** 下载明确版本的模型，输入提示词及生成参数，先查看容量计划，再提交一个完全离线执行的作业。
3. **学习者：** 查看模型分块、每块运行位置、每步通信量、各设备计算耗时，理解为什么设备参与或未被使用。
4. **移动设备用户：** 前台加入作业，明确看到保持运行的要求；临时退出时了解影响。不得声称后台运行能力已经可靠实现。
5. **后端贡献者：** 按协议增加平台或模型适配器，通过一致性测试后向集群报告能力。

## 4. 范围与交付阶段

阶段是开发顺序，不是缩小最终范围。每个阶段的证据必须独立标记。

| 阶段 | 可交付行为 | 不足以证明的目标 |
| --- | --- | --- |
| G0 研究与设计 | 核验 H3；测量设备；冻结 PRD、协议 spec、测试计划 | 不能证明目标模型能分布式运行 |
| G1 通信与正确性 | Windows、Mac、iOS 真节点运行同一小型计算图的不同部分；验证结果误差 | 不能证明 H3 内存或算子可行 |
| G2 H3 双桌面 | Windows CUDA 与 Mac 后端运行同一次 H3 推理中的真实模型计算；产生有效视频 | 不能证明 iPhone 已参与生成模型计算 |
| G3 H3 手机计算 | 至少一台、继而两台 iPhone 执行同一次目标作业中经验证的模型计算；透明记录职责 | 手机预览或传文件不满足该阶段 |
| G4 容量证明与产品交付 | 同一模型及配置证明集群解决单节点内存限制；全流程安装、恢复、CI、跨代理 PR 与最终硬件测试 | 仅全部单元测试通过不满足交付 |

模型内部切分是必须研究和实现的容量扩展路径。组件级分配可先落地，但若完整生成网络仍只能由一个节点容纳，不得宣称完成了该网络的跨设备容量扩展。

若 H3 的许可、算子或资源门槛导致当前设备无法执行，必须交付具体证据和未完成项。替代小模型只能证明基础设施，不能自行替换 H3 目标或把最终状态改为完成。手机如只能运行前后处理，必须明确其贡献与限制，并继续保留模型计算目标。

## 5. 核心用户流程与 UX

### 5.1 创建集群与配对

用户在一台桌面选择“创建集群”，其余设备选择“加入”。初始版本允许手动地址和短期配对码；局域网发现作为便捷路径。二维码不得包含长期明文密钥。双方展示设备名称和需授予的能力，用户确认后建立持久设备身份。

面板对每台设备展示：平台、后端、连接状态、最近心跳、可用内存预算、已分配权重、运行临时内存、温度/电源信息（平台提供时）及模型兼容性。未知字段显示“未知”，不能填零或估计成真实值。

### 5.2 选择模型与安装

展示模型来源、精确版本、许可、文件清单、校验值、下载体积、预期磁盘开销和兼容配置。用户可导入本地模型包。首次下载可联网，完成后必须支持断外网运行。外部 API、云端提示改写或远程生成不属于离线执行。

同一模型的不同精度、组件替换、裁剪和音频开关必须作为不同配置显式呈现；不得把降级配置的结果标为完整原版。下载可恢复，校验失败不得加载。清理模型前要显示被哪些任务使用。

### 5.3 配置与提交作业

用户输入提示词、种子、分辨率、帧数/时长及模型支持的参数。提交前生成放置计划，展示每个组件/分块运行位置、保守内存预算、预计通信量及估计依据。估计不足时显示“待测”，不显示虚构耗时。

用户可手动指定设备和分块，便于学习和排错。自动规划不得覆盖用户的资源上限；不兼容或容量不足必须在运行前给出可操作理由。

### 5.4 运行、暂停、恢复与结果

进度包含下载、加载、编码、去噪步数、解码、保存；长操作显示心跳和最近进展，区分慢与失联。展示当前执行节点和实际计算时间。顺序分块等待属于正常状态，不能伪装成所有设备一直并行。

暂停在安全检查点生效；停止会取消未执行工作并清理临时资源。失败时保留日志与最近完整检查点。恢复必须校验模型、配置、调度器状态和必要随机状态；无法恢复时明确说明必须重算的范围。

结果包含可播放的视频及作业清单：模型和软件版本、参数、设备、分块、各节点真实计算与传输数据、耗时、内存峰值、是否降级、是否恢复。默认保存在用户指定的本地目录。

## 7. 权限、隐私与资源政策

仅配对节点接收任务与模型分片；节点执行受支持的模型操作，不接受任意远程 shell 或动态代码。通信需要身份认证、加密和消息完整性保护。设备名称不作为可信身份。

用户要能明确知晓：参与节点可能接收到提示词、输入素材、中间张量或生成结果；这些数据不能被保证对参与节点的所有者保密。默认只允许用户信任的个人局域网设备，不自动发现或接入公网陌生算力。

日志默认不存完整提示词、输入媒体、密钥或张量原文。诊断导出应展示包含的文件并去除秘密。模型缓存、临时张量和输出分别有清理策略；清理不得删除用户选定目录之外的文件。

设备所有者可以设置内存上限、是否允许电池运行、是否保持前台、是否允许保存模型分片。运行时不得绕过 iOS 平台限制。进入后台、内存压力、发热或电量不足时报告状态并走可解释的暂停/恢复路径；后台持续 GPU 能力须按系统版本实测后启用。

## 8. 容量、性能与可靠性

优先级是正确生成、容量扩展、可恢复，再是速度。首版不设置无证据的 token/s 或视频分钟数承诺，也不以无限等待掩盖死锁。每个阶段须有活动心跳、无进展检测及人工取消入口。

必须记录：模型权重驻留、CPU 内存峰值、GPU/统一内存使用（按平台实际可测指标说明）、单步耗时、网络字节数、有效带宽、权重加载流量、恢复成本、输出可播放性。不同平台不可直接相加的指标不得在 UI 中混为“总显存”。

容量对照采用完全相同的模型版本、精度、参数和组件。单节点失败须有真实的容量证据或明确的安全预检证据，并分别标注；不同量化配置之间的比较不能证明分布式容量收益。

某节点退出后，只有剩余节点有足够资源和后端能力才可迁移重算；否则进入等待设备/用户动作状态。产品不承诺在任意设备丢失时仍能完成。

## 9. 真实硬件证据分级

| 等级 | 证据 | 可以宣称 |
| --- | --- | --- |
| E0 | 设计、模拟、静态审查 | 方案存在 |
| E1 | 单元测试、虚拟节点、CPU 数值参考 | 受测代码逻辑与协议性质 |
| E2 | 单个平台真实后端，含模拟器时必须注明 | 该后端的受测运算可运行 |
| E3 | Windows + Mac 真机同一 H3 作业 | 桌面异构目标工作负载可执行 |
| E4 | 两台 iPhone 真机加入同一 H3 作业并计算 | 四节点目标链路可执行 |
| E5 | 同配置容量对照、离线恢复、重复生成及安装复现 | 产品最终范围已得到相应证据支持 |

每个能力单独评级。Mac 上通过测试不能推断 Windows 或 iOS 已验证；iOS 模拟器不能替代 iPhone 真机；成功生成一次不能证明恢复可靠性。最终交付必须达到 E5 所定义的相关证据，缺失部分保持未完成状态。

## 10. SDD、TDD 与协作流程

实现前产出模型研究、架构、协议、作业状态机、后端契约、检查点格式及测试计划；每项以 PRD 编号追踪到 spec、测试与代码。需求变更先更新 spec 并说明兼容性。

每个实现任务先提交能体现需求且初始失败的测试，再实现和重构。测试覆盖正常、错误、边界和故障恢复；不以复制实现逻辑的断言充数。真实硬件测试无法运行时记录缺口，不用 mock 冒充。

方案先进行产品、架构、质量视角的小会评审，记录争议与决定；修订后进行第二轮独立审查并冻结可实现的接口。研究未知项不得通过文字表决变成“已验证”。

各实现代理在独立分支提交 GitHub PR，禁止作者自审。另一个代理提供带证据的审查，CI 必须通过且阻塞意见已解决才合并到主分支。GitHub 同账户导致无法原生批准时必须保留角色独立的审查证据并报告平台限制，不能伪称完成原生 approve。

CI 包含协议/单元测试、集成测试、平台可运行的构建和静态检查；特权或真机检查作为明确的硬件门禁。禁止把整个真机测试默默 skip 后宣称全平台绿灯。合并后进行一轮覆盖全部需求的系统验收，输出要求—证据—结论矩阵。

## 11. 待研究门槛与决策

| 门槛 | 必须得到的证据 | 未通过时处理 |
| --- | --- | --- |
| H3 身份与许可 | 官方模型卡、权重、推理代码、许可及精确版本 | 保留目标待核验；不下载未核实大文件 |
| H3 切分 | 计算图依赖、各组件/块权重与峰值、边界张量形状 | 调整切分设计；不能套用 LLM RPC 成功结论 |
| Apple 运算 | Mac 与 iOS 对实际算子、精度、量化格式的执行及误差 | 明确需移植的算子，分别评估 CPU/GPU 回退 |
| iPhone 可装载块 | 真机可用内存、App 安装、前后台行为、热稳定性 | 保留手机目标并报告缺口；不把缓存角色冒充模型执行 |
| 总容量 | 当前设备真实峰值预算与可行放置方案 | 先优化内存、量化和分块；配置变动必须透明 |
| 网络可承受性 | 实测各边界张量、带宽、总通信耗时 | 减少边界、调整分块；不凭 Wi-Fi 名称估算速度 |

初始产品选择：局域网、受信任设备、集中协调、显式放置计划、前台 iOS、可观测的慢速执行。它们便于验证目标，未来可通过协议演进扩展；不包含多租户算力市场、训练、收费结算或互联网陌生节点。
