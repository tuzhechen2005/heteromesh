## 结论与完成边界

原始目标**尚未完成**：Windows、Mac 与两台 iPhone 共同运行指定 H3 视频生成模型，并证明多设备扩大了单任务可用容量。当前已完成有真实运算的协议、受控执行、桌面开发入口，以及单台 Mac 上 CPU/MPS 分进程合作的小 Transformer 验证；它们是基础设施证据。

已核验的证据包括 `docs/testing/evidence/cli.md` 中四个真实 HTTPS 任务 NumPy→MPS→NumPy→MPS，最终最大绝对误差 `1.1920928955078125e-07`。这是同一物理 Mac 上的异构执行，既不是 Windows–Mac 双机验收，也不是视频生成、iPhone 计算或容量扩展证明。

## 正在开发的 PR 不等于目标验收

快照时 #7 为固定 H3 元数据与源码契约；#12 为上游真实 block 类的缩小配置/自有权重执行路径。二者能减少模型适配的不确定性，但没有证明官方完整权重已加载，更没有生成 H3 视频。

#8 开发 Swift worker 与前台 iOS App，并有同 Mac 跨语言 HTTPS 验证；在手机不可访问期间保持 iPhone 真机项 NOT_RUN。#11 修复 checkpoint 回退分支污染，但仍是进度账本保护。#13 交付开发 wheel/sdist，不以打包成功或自报 JSON 作为稳定 H3 能力发布许可。

这些 PR 合并后应更新“软件实现”项；除非另附对应真实实验，物理设备、目标视频和容量项的状态不变。

## 推进完整目标的依赖顺序

1. **真实模型装载与 profile 定义。**固定适用授权、权重 revision、生成尺寸/帧数、精度、是否含音频；逐 tensor 或受控分片读取，不先构造完整大模型。量化或替换组件需明确不同 profile。测量 CUDA/MPS 的加载与运行峰值。
2. **完整 H3 计算图。**将文本编码、输入投影/refiner、packed 音视频布局、连续主 blocks、输出投影、两条 scheduler、视频/音频解码组成可执行图。仅主 blocks 的拼接不能代替全部流程。先单机参考，再双桌面单步比较，再完整视频。
3. **iPhone 真实分片。**完成签名与前台 App 部署，选择可实现的 Core ML/Metal 等后端，验证真实 H3 运算/量化、内存和温控。需要手机真机参与；不能将数据转发、预览或格式转码计为模型计算贡献。
4. **模型检查点。**定义版本化 model-state 文件、内容摘要及原子索引，保存音视频 latent、两个 scheduler、RNG、条件引用和模态布局。故障注入要比较恢复后的模型状态与参考；SQLite cursor 单独不够。
5. **容量与网络实验。**先固定模型/profile/卸载策略，测逐节点 CPU/GPU/统一内存峰值、激活大小、传输总量和总耗时。完成单节点与集群对照；人为降低内存限制只能称受限预算实验。
6. **四节点最终验收。**Windows、M4 Mac、两台 iPhone 同一次生成贡献证据、可播放视频、断 WAN、节点断开/恢复、用户取消、数据清理和干净安装。全部证据绑定最终 commit、manifest/profile 与设备版本。

无需等手机可用才能继续 1、2、4、5 的研究与实现，但不得在未验证手机时关闭原始目标。若许可、实际容量或算子成为外部阻碍，应保留可复现失败和明确所需资源，而非把成功标准改成 tiny demo。
